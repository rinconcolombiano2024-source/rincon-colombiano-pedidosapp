HALLAZGOS

1. El mensaje "correo o contrasena incorrectos" se recibe directamente de Supabase Auth.
   Ocurre antes de consultar el rol platform_admin.
2. La app mostraba siempre un mensaje generico despues de solicitar recuperacion,
   incluso cuando Supabase devolvia un error.
3. El proveedor integrado de correo de Supabase es de prueba, tiene limite bajo
   y puede rechazar destinatarios que no pertenecen al equipo del proyecto.
4. El rol platform_admin se asignaba por migracion. Si el usuario fue creado
   despues de ejecutar esa migracion, el rol podia quedar sin asignar.
5. La pantalla podia mostrar el formulario de nueva contrasena usando solamente
   ?recovery=1, aunque no existiera una sesion de recuperacion valida.

CORRECCIONES

1. Errores claros de credenciales, confirmacion, limite, destinatario, URL y red.
2. Manejo de excepciones de red en login y recuperacion.
3. Bloqueo temporal de botones durante la solicitud.
4. Validacion backend de is_platform_owner despues del login.
5. Validacion de sesion antes de permitir cambiar la contrasena.
6. Migracion V67 para verificar la cuenta y activar el rol exacto.
