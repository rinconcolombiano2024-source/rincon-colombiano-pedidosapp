MEMORIA DE LA APP - RINCON COLOMBIANO

Regla principal:
- No quitar, borrar ni reemplazar funciones existentes sin pedido claro del usuario.
- No inventar cambios fuera de lo solicitado.
- Cada cambio debe conservar lo ya hecho: pedidos, tickets, impresion, cierre mensual, edicion de menu, Supabase, modo offline y PWA.

Funciones actuales que deben conservarse:
- App de pedidos para restaurante RINCON COLOMBIANO.
- Tomar pedidos desde categorias y productos.
- Buscador en menu rapido del restaurante para encontrar productos por nombre, categoria o descripcion sin bajar por todo el menu.
- Pedido actual se guarda como borrador local mientras se esta tomando; si se recarga la tablet, se recupera sin generar ticket hasta guardar/imprimir.
- Categorias editables: agregar, cambiar nombre y eliminar.
- Categorias repetidas por mayusculas, espacios o acentos se limpian desde Eliminar: queda una sola categoria con sus productos y se guarda.
- Productos editables dentro de cada categoria: agregar, editar precio, editar nombre y eliminar.
- Productos tienen disponibilidad editable: Disponible / No disponible.
- Productos pueden tener foto mediante link o foto pequena cargada en el editor.
- Productos pueden tener descripcion/explicacion para el cliente; se muestra en el menu del restaurante y en cliente QR.
- Fotos cargadas de productos se optimizan/comprimen antes de guardarse para que el menu del cliente sea mas rapido y profesional.
- Aviso visual pequeno cuando se agregan, editan, guardan, restauran o eliminan categorias/productos/ajustes.
- Al guardar un producto, el aviso debe decir: Producto guardado.
- Menu base vacio para restaurantes nuevos: el restaurante crea categorias, productos, fotos, precios y disponibilidad.
- Producto especial/manual con precio.
- Tipo de pedido cliente/restaurante: Comer en el punto, Para llevar / recoger en el punto, Envio a domicilio.
- Metodo de pago por pedido: Pago en caja, Efectivo, Transferencia y Datafono / tarjeta.
- Nombre del cliente o mesa.
- Domicilio puede guardar nombre, telefono, direccion, barrio/ciudad, referencia, distancia km y costo estimado.
- Domicilio usa minimo configurable por restaurante, por defecto 20 PLN; si la tarifa por km supera ese minimo, usa 4.50 PLN hasta 1.5 km; de 1.5 a 6 km suma 1.50 PLN/km; de 6 a 8 km suma 2.50 PLN/km; mas de 8 km suma 3.50 PLN/km.
- Domicilio puede calcular distancia real con Google Maps si se configura direccion del restaurante y Google Maps API key con Maps JavaScript API, Distance Matrix API y Geocoding API.
- Cliente puede permitir ubicacion para calcular domicilio con Google Maps desde su posicion real.
- Usar ubicacion del cliente obtiene coordenadas reales; con Google Maps API key tambien intenta completar direccion aproximada y calcular distancia real.
- Restaurante puede guardar ubicacion actual desde la tablet como direccion/coordenadas exactas del local.
- Restaurante puede subir logo y guardar datos legales/profesionales: nombre comercial, razon social, identificacion fiscal, telefono, correo y direccion legal.
- Al abrir QR cliente, la app intenta sincronizar primero el menu real actual del restaurante a Supabase.
- El link QR nuevo incluye version de app para ayudar a que telefonos con cache vieja abran la version nueva.
- Boton Actualizar en restaurante: refresca app/nube sin borrar el pedido actual.
- Nombre de la persona que tomo el pedido.
- Responsable del turno: se pide al iniciar sesion y se aplica automaticamente a pedidos nuevos.
- Boton Turno para cambiar quien toma pedidos durante el dia.
- Nota general del pedido.
- Nota individual por plato.
- Notas del pedido y de cada plato siempre en MAYUSCULAS, resaltadas en negrita para cocina/ticket.
- Boton Corregir pedido para dejar claro que un pedido abierto puede editarse y guardarse otra vez.
- Boton Cancelar pedido para eliminar/cancelar el pedido actual con confirmacion, quitandolo del historial y cierres.
- Ticket de cocina impreso con numero consecutivo.
- Impresion preparada como pagina/trabajo individual con salto de pagina y avance final reforzado para ayudar al corte automatico si la impresora o driver lo tiene activado.
- PDF de recibo/ticket con ancho configurable en milimetros para impresoras de distintos tamanos.
- Ticket diario reinicia cada dia.
- Boton para cambiar manualmente el proximo numero de ticket.
- Historial de tickets del dia.
- Abrir y reimprimir tickets guardados.
- Cierre de caja diario con total caja, tickets, productos, promedio, tipo de pedido, responsable y productos vendidos.
- Cierre de caja diario incluye resumen por metodo de pago.
- Los reportes diario/mensual convierten cantidades y precios a numero antes de sumar para evitar fallas de cuentas.
- Impresion del cierre de caja diario.
- Cierre mensual con total vendido, tickets, productos, promedio, detalle por dia y productos vendidos.
- Impresion del cierre mensual.
- Modulo cliente por QR: cliente.html permite ver menu, armar carrito y enviar pedido pendiente.
- Modulo cliente por QR tiene selector de idioma: Espanol, Polski e English.
- El selector de idioma traduce textos, botones, mensajes, domicilio, pago, notificaciones y chat del cliente QR.
- Los mensajes de acceso del cliente tambien respetan el idioma seleccionado.
- Cliente QR tiene cuenta propia con correo electronico y contrasena usando Supabase Auth.
- Cliente puede crear cuenta, iniciar sesion y cerrar sesion desde cliente.html.
- Al crear cuenta cliente, se pide nombre completo, telefono, direccion, barrio/ciudad, referencia y aceptacion del tratamiento de datos para pedidos, historial, entrega, chat y cookies tecnicas.
- Despues del registro, la app avisa al cliente que debe revisar su correo electronico y confirmar la cuenta antes de iniciar sesion si Supabase tiene confirmacion activa.
- La pantalla principal ahora muestra una entrada separada para cliente: Entrar / registrar cliente.
- Cliente puede entrar sin QR, crear cuenta, buscar restaurante publicado, elegirlo y luego tomar el pedido.
- Si el cliente entra por QR con store, la app abre directamente el restaurante del QR.
- Restaurante publica perfil basico para busqueda de clientes: nombre comercial, logo, direccion publica, telefono y estado activo.
- Al guardar ajustes o menu, la app del restaurante intenta actualizar su perfil publico sin borrar ni cambiar pedidos existentes.
- Para enviar pedido desde cliente QR se requiere cuenta de cliente iniciada; asi el pedido queda guardado en su historial.
- Cliente tiene seccion Mis pedidos con historial, estado, total, ticket si ya fue aceptado y boton para abrir estado/chat del pedido.
- Cliente QR tiene buscador de productos por nombre, categoria o descripcion.
- Cliente QR tiene boton Actualizar menu para recargar el menu real configurado por el restaurante.
- Cliente QR deduplica restaurantes publicados con el mismo nombre y la misma direccion para evitar ver dos veces la misma sede.
- Si solo hay una sede publicada, Cliente QR entra directo al menu y muestra el restaurante en formato compacto tipo app.
- La pantalla cliente en movil usa cabecera compacta, aviso legal desplegable y selector de restaurante reducido para verse mas como app instalada.
- Cliente escucha cambios del menu en vivo con Supabase Realtime filtrado por el restaurante seleccionado.
- Cuando el restaurante cambia precios, productos, categorias, fotos, descripciones o disponibilidad y guarda, el cliente intenta actualizar el menu automaticamente sin cerrar la app.
- Si se pierde internet, al volver la conexion la app cliente vuelve a refrescar el menu y reactiva la sincronizacion en vivo.
- Los pedidos cliente guardan snapshot de producto: product_id, product_name_snapshot, unit_price_snapshot, quantity, options_snapshot y total_snapshot, manteniendo campos viejos name/price/qty para compatibilidad.
- Cliente tiene perfil basico guardado: nombre, telefono, direccion preferida, referencia, distancia e idioma.
- Los pedidos QR guardan customer_user_id para asociar pedidos a la cuenta del cliente sin mezclar clientes.
- Los nombres de productos/categorias escritos por el restaurante no se traducen automaticamente; se muestran tal como se guardaron en el menu.
- App restaurante tiene QR cliente y bandeja Pedidos cliente para aceptar, generar ticket consecutivo e imprimir cocina.
- La bandeja Pedidos cliente permite marcar Pedido enviado y Pedido entregado despues de aceptar/imprimir.
- Cliente puede ver y recibir notificacion del navegador para estados: pendiente, aceptado, enviado, entregado o cancelado.
- QR cliente es general por defecto; la mesa/ubicacion es opcional.
- Cliente puede elegir metodo de pago, poner notas, pedir domicilio con datos completos y ver costo estimado.
- Cliente ve modulo de pago despues de enviar: total exacto, referencia del pedido y metodo elegido.
- Si cliente escoge transferencia, la app muestra cuenta bancaria y texto de comprobante configurados por el restaurante.
- Si cliente escoge efectivo o datafono, la app muestra total y referencia para pagar en caja o al recibir.
- Chat basico por pedido entre cliente y restaurante.
- Cliente puede enviar mensaje y foto del comprobante de transferencia en el chat del pedido.
- Cajero puede ver el comprobante en Pedidos cliente y responder con texto o imagen.
- Las imagenes del chat se comprimen antes de enviarse para no guardar fotos pesadas.
- Cliente puede activar notificaciones del navegador para recibir aviso de estado del pedido.
- Restaurante puede activar notificaciones del navegador junto con alarma sonora para pedidos nuevos.
- Cliente puede ver estado del pedido: pendiente, aceptado, enviado, entregado o cancelado, usando referencia publica segura en Supabase.
- La app cliente muestra advertencia de app de prueba y confirmacion de ajustes ante errores.
- La app cliente muestra aviso de tratamiento de datos/cookies tecnicas y exige aceptacion al crear cuenta.
- La app restaurante tiene alarma sonora para pedidos cliente pendientes; el cajero debe tocar Activar alarma una vez por restricciones del navegador.
- Nombre del restaurante editable: por defecto RINCON COLOMBIANO, pero cada cuenta de restaurante puede guardar su propio nombre para pantalla, cliente QR, tickets, PDF y cierres.
- Logo del restaurante editable y visible en restaurante y cliente QR.
- Moneda editable: simbolo, posicion y formato.
- Ancho de ticket editable en milimetros para impresion/PDF.
- Recargo fijo opcional de domicilio editable para el modulo cliente.
- Minimo de domicilio editable para el modulo cliente.
- Direccion del restaurante y Google Maps API key editables para calcular distancia real.
- Cuenta de transferencia y texto de comprobante editables para el modulo cliente.
- Cobro externo por tienda desactivado por decision del restaurante hasta confirmar una integracion real con proveedor de pago.
- La app no cobra comisiones: los pagos se manejan por caja, efectivo, transferencia o datafono segun el restaurante.
- Inicio de sesion por correo electronico y contrasena usando Supabase.
- Registrar restaurante con datos legales y consentimiento tecnico.
- Acceso inicial tiene entrada separada para Cliente, Restaurante y Colaborador.
- Nueva base de roles multiples: customer, restaurant_owner, restaurant_admin, restaurant_employee, restaurant_courier, platform_courier y platform_admin.
- Una misma cuenta de Supabase Auth puede activar varios roles sin crear otro correo.
- Cliente activa rol customer al iniciar sesion o crear cuenta.
- Restaurante activa rol restaurant_owner al iniciar sesion.
- Colaborador tiene pagina propia colaborador.html con registro, inicio de sesion, solicitud y estado pendiente de revision.
- Colaborador independiente usa rol tecnico platform_courier y queda en pending_review hasta aprobacion administrativa.
- Recuperar contrasena por correo electronico.
- Guardar nueva contrasena desde enlace de recuperacion.
- Sincronizacion con Supabase: menu, moneda, pedidos y contador de tickets.
- Modo sin internet: permite seguir tomando pedidos y guardarlos localmente.
- Pedidos sin internet quedan como Pendiente nube.
- Cancelaciones sin internet quedan pendientes para eliminarse de la nube cuando vuelva la conexion.
- Cuando vuelve internet, la app intenta sincronizar automaticamente.
- Boton Descargar app visible.
- Ventana de ayuda para instalar/agregar a pantalla principal si el navegador no permite instalacion directa.
- PWA con manifest, icono y service worker.
- Compatibilidad PWA para Android, iOS/iPadOS, Windows, Mac y navegadores modernos.
- Pantallas responsive: cliente QR se reorganiza a una columna en telefono y mantiene selector de idioma visible.
- Metadatos PWA/iOS/Android reforzados con viewport-fit, manifest y apple-touch-icon.
- Iconos PNG para instalacion en Android/iOS y SVG como respaldo.

Configuracion Supabase actual:
- URL del proyecto: https://ouulrehcgmfbettseibn.supabase.co
- La URL no debe llevar /rest/v1/.
- La app usa publishable key en supabase-config.js.
- No usar secret key en la app ni en GitHub.

Archivos importantes:
- index.html: estructura de pantalla, login, pedidos, dialogos.
- app.js: logica de pedidos, tickets, Supabase, offline, cierre mensual y pedidos cliente.
- cliente.html / cliente.js: modulo para que el cliente pida desde QR.
- colaborador.html / colaborador.js: modulo separado para registro e inicio de sesion de colaboradores.
- styles.css: diseno responsive para PC y telefono.
- service-worker.js: cache de PWA.
- supabase-config.js: URL y publishable key.
- supabase-schema.sql: tablas, politicas RLS y funciones RPC.
- MIGRACION-FASE2-REALTIME-MENU.sql: migracion corta para activar Supabase Realtime del menu sin reejecutar todo el esquema.
- MIGRACION-FASE3-ROLES-ACCESOS.sql: migracion segura para perfiles generales, roles multiples y colaboradores.
- Supabase requiere ejecutar el SQL actualizado cuando se agreguen cuentas de cliente, customer_profiles, customer_user_id o historial.

Notas para telefono:
- Si el telefono no muestra cambios nuevos, desinstalar la app vieja y volver a instalar desde la URL de Vercel.
- El service worker debe subir version cada vez que cambie la app.
- Version de cache actual al crear esta memoria: rincon-colombiano-v54.

Precaucion offline:
- Si varias tablets trabajan sin internet al mismo tiempo, pueden repetirse numeros locales de ticket.
- Para evitar conflictos en hora pico sin internet, usar una tablet principal o mantener conexion estable.
