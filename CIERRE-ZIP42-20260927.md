# RC ORDERA — cierre sobre ZIP (42)

Base exclusiva: rincon-colombiano-pedidosapp-main (42).zip. Se conserva el original.
Este cierre contiene solamente el trabajo terminado antes de la solicitud de empaquetado.

## Archivos funcionales modificados

- `auto-translate.js` y `www/auto-translate.js`:
  - líneas 18, 870–938: solicitudes simultáneas del mismo texto/idioma comparten una operación; timeout de 10 segundos con AbortSignal real; se cachean también traducciones válidas que conservan el texto. Los fallos mantienen la pausa existente, no se cachean como éxito.
  - líneas 1021–1070: una respuesta tardía no pisa un texto/atributo que otro módulo acaba de modificar.
  - líneas 1112, 1150: evita reescribir el título sin cambios y traduce atributos del propio elemento añadido.
  - líneas 1366–1409: conserva cambios de DOM que llegan durante una traducción, procesa raíces secuencialmente, descarta raíces desconectadas y no reprocesa mutaciones del título o del propio traductor.
  - No se cambian textos existentes, idiomas, proveedor, endpoint ni diccionarios.
- `mesero.js` y `www/mesero.js`:
  - referencias de controles y estado de recuperación; protección en `waiterAuthorize` (línea 1669).
  - líneas 1804–1890: solicitud de correo, formulario de nueva contraseña, cancelación y guardado usando Supabase Auth existente. Una sola solicitud a la vez; enlace conserva `store`; contraseña no se escribe en almacenamiento ni logs.
  - líneas 1980–2005: recuperación no abre estaciones/Realtime antes de terminar; las llamadas de autorización salen del callback de Auth antes de consultar Supabase.
  - enlaces sin sesión no permiten actualizar contraseña; errores permiten reintento manual sin disparar un bucle automático.
- `mesero.html` y `www/mesero.html`, líneas 58–72: botón de recuperación y formulario de nueva contraseña con estilos existentes. No se eliminan controles existentes.

- `npm run qa`: 61 pruebas aprobadas, 0 fallos. QA estático aprobado e i18n: 2066 comprobaciones aprobadas.
- `npm run qa:e2e`: 22 pruebas aprobadas, 0 fallos.
- Al inicio: QA 61/61; navegador 5/12, con 7 fallos por ruta/mocks desfasados. Esos fallos del entorno de pruebas se corrigieron sin relajar las expectativas funcionales existentes.
- Las pruebas existentes de añadir al carrito, escape de contenido y cambio de restaurante pasan. No se cambió `cliente.js` ni la lógica del carrito: no hubo reproducción concreta del fallo descrito por el usuario antes del cierre.
